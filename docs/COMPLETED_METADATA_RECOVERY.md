# 완료함 세부정보 누락 조사·복구 (2026-11-17)

## 증상과 조사

웹사이트에서 완료 처리한 일정인데 완료함에서 ‘휴대폰·구글 캘린더에서 만든 일정’으로 표시되고 대상자·관리군·메모 등의 세부정보가 비어 보이는 증상입니다. 이 문구는 기기를 감지한 결과가 아니라 `vhm_kind` 비공개 속성이 없을 때 표시하던 안내였습니다. 따라서 문구만으로 휴대폰에서 등록한 일정이라고 판단할 수 없습니다.

기존 구현은 완료/되돌리기에서 Google Calendar `events.move` 결과에 원래 `extendedProperties.private`가 그대로 남는다고 가정했습니다. 비공개 속성은 캘린더별 일정 사본에 속하므로 이동 후 보존을 검증해야 합니다. 기존 가짜 Google 서버는 한 객체를 그대로 다른 배열로 옮겨 이 문제를 검출하지 못했습니다. 이번에는 이동 후 목적지의 비공개 속성이 없는 과거 사례와 캘린더별 별도 객체·삭제 표식을 재현하도록 테스트했습니다. 사용자 실제 Google 응답과 원자료는 접근할 수 없어 확인하지 못했습니다. Google 공식 문서 URL 요청도 환경의 HTTP 403으로 열지 못했습니다.

## 신규 완료 처리 보호

1. 원본을 읽고 최신 ETag와 세부정보를 확보합니다. 저장할 때 기존 비공개 속성의 알 수 없는 필드도 보존합니다.
2. 목적지에 세부정보를 명시적으로 복사합니다. 사용자 이름·메모를 설명이나 공유 속성으로 옮기지 않으며 기존 메모 암호문을 유지합니다. 참석자 초대는 복사하지 않고 전송 옵션은 `sendUpdates=none`을 사용합니다.
3. 목적지를 다시 읽어 제목·일시·알림·비공개 속성을 검증합니다. 보존을 확인하지 못하면 원본을 삭제하지 않습니다.
4. 원본을 ETag 조건부로 삭제합니다. 다른 기기에서 수정했다면 삭제하지 않고 충돌로 반환합니다. 이 과정에서 만든 목적지 사본은 해당 사본이 수정되지 않은 경우에만 정리합니다.
5. 같은 ID의 삭제 표식 때문에 다시 만들 수 없으면 결정적인 대체 ID를 사용하고 이전 ID를 비공개 속성에 보관해 후속 일정 연결을 지원합니다. 앱 UID는 유지합니다. 같은 시도 재실행 시 기존 사본의 내용이 일치하는 경우 재사용하고 다른 내용은 덮어쓰지 않습니다.

완료 취소, 업무↔개인, 종일↔시간 변경의 기존 복사/삭제 경로에도 검증을 적용했습니다. 이동에 실패한 경우 원래 캘린더에 완료 상태의 일정이 남을 수 있으며, 새로고침 후 세부정보를 확인하고 완료함의 기존 이동 기능으로 재시도할 수 있습니다. 이는 원본 보존을 우선하는 처리입니다.

## 이전 데이터 복구 방법

웹사이트에서 Google 계정 연결 후 문제가 있는 월의 **완료함**을 엽니다.

- **누락된 세부정보 복구**: 원래 업무·개인 캘린더에서 동일 일정 ID의 잔존 사본(삭제 표식 포함)을 확인합니다. 앱 종류와 UID 또는 일치하는 iCalUID 등 근거가 있는 자료만 이용합니다. Google이 원본 속성을 더 이상 반환하지 않으면 이 방법으로 복구할 수 없습니다.
- **백업 JSON에서 세부정보 복구**: 이 사이트에서 내려받은 `일정백업_*.json`을 선택합니다. 브라우저에서 읽고 기존 완료함 일정과 정확한 ID, 또는 iCalUID와 발생 일시가 일치하는 자료만 이용합니다. 백업 파일 전체를 별도 서버에 올리지 않습니다.

두 작업은 현재 표시 월의 기존 완료함 일정에 비공개 세부정보만 보충합니다. 새 일정을 만들거나 현재 제목·시작/끝 날짜·시간을 바꾸지 않습니다. 암호문 메모와 이미지 참조도 가능한 원본 그대로 보존합니다. 완료한 일정의 기한 알림을 새로 만들지 않습니다. 이미 정상 앱 태그가 있는 일정은 덮어쓰지 않으므로 수동으로 편집한 내용을 과거 백업으로 되돌리지 않습니다.

복구 근거가 없거나 서로 다른 내용의 후보가 있으면 추측하지 않습니다. 동시 수정은 ETag로 감지하고 건너뜁니다. 완료 후 복구·이미 정상·근거 없음·불일치·동시 수정·실패 건수를 화면에 표시합니다. 원본과 백업 양쪽에서 사라진 세부정보는 제목이나 날짜만으로 재구성할 수 없습니다.

## 실제 복구와 검증 범위

이번 실행 환경에는 사용자 Google 계정 접속 도구·로그인 세션·실제 백업 파일이 없었습니다. 따라서 실제 일정의 손상 여부나 복구 건수를 확인하지 못했고, 사용자 자료를 복구 완료했다고 보고할 수 없습니다. 복구 기능을 배포하여 사용자가 자신의 로그인 상태에서 실행하고 결과를 확인할 수 있게 했습니다. 실제 개인정보를 개발·테스트에 사용하지 않았습니다.

`tests/test-completed-recovery.js`는 목적지 속성 누락·삽입 실패·원본 동시 수정·삭제된 ID 충돌·잔존 원본 복구·옛 UID 없는 자료·백업 JSON 버튼 경로·근거 없는 자료·불일치 후보·반복 복구·4개 화면 폭을 확인합니다. 기존 일정 테스트도 메모 암호화·완료 취소·기한 알림·백업·개인 일정 동작을 검증합니다. 원본/목적지를 실제처럼 별도 객체로 바꾸고 가짜 이벤트 ID 및 객체 참조 의존 테스트를 수정했습니다.
