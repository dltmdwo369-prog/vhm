# 다른 사용자에게 안내할 개인별 사용 방법

## 이용에 필요한 것

공개 연계자료 검색과 교육자료 열람에는 GitHub 계정이나 ChatGPT 유료 구독이 필요하지 않다. 이 웹사이트의 실행에 ChatGPT/OpenAI API를 사용하지 않는다.

개인 일정·연계 목록·공문/양식 파일을 저장하려면 본인 Google 계정과 앱의 Google Calendar/Drive 연결 권한이 필요하다. 운영자는 다른 사용자가 현재 OAuth 앱에 로그인할 수 있는지 확인해야 한다. Google 동의 화면이 테스트 상태라면 테스트 사용자 등록이 필요할 수 있고, 공개 운영으로 전환할 때는 요청 권한에 따른 Google 검토가 필요할 수 있다. 현재 동의 화면의 실시간 상태와 타 계정 로그인 가능 여부는 이번 작업에서 확인하지 않았다.

## 그대로 전달할 안내문

> 방문건강관리 업무사이트는 기존 웹주소에서 이용할 수 있습니다. GitHub 가입이나 ChatGPT 결제는 필요하지 않습니다.
>
> 공개 연계자료는 바로 검색할 수 있고, 개인 자료를 저장하려면 본인 Google 계정으로 연결한 뒤 ‘연계 안내 → 개인 목록·드라이브 연결’을 누르세요. 개인 서비스와 첨부 양식은 본인 Drive에 저장되며 다른 이용자의 목록과 자동 공유되지 않습니다.
>
> 필요한 연계서비스를 추가하거나 기존 공개사업의 공문·양식을 첨부해 나에게 맞는 목록을 만들 수 있습니다. 사용할 기능은 ‘설정 → 사용할 기능’에서 켜고 끕니다. 실제 대상자 정보가 담긴 서류 대신 개인정보를 제거한 공문과 빈 신청양식만 올려주세요.

## 개인 연계 목록 꾸미기

1. 사이트에서 본인 Google 계정으로 연결한다. 일정 메뉴를 숨겼다면 설정의 Google 연결을 이용한다.
2. ‘연계 안내 → 개인 목록·드라이브 연결’로 본인 자료를 불러온다. 처음에는 저장된 목록이 없을 수 있다. 읽기만으로 공개자료가 Drive에 자동 복사되지는 않는다.
3. ‘서비스 목록 → 개인 서비스 추가’로 서비스를 등록한다. 이름·기관·조건·연락처·해당 요구 등은 원하는 만큼 편집한다.
4. 공문·빈 신청양식 파일을 첨부하면 서비스명이 비어 있을 때 파일명으로 채운다. ‘저장’을 누르면 개인 자료 등록 완료로 표시되며 내 확인 대기에서 제외된다. 추가 필드를 필수로 입력할 필요는 없다.
5. 요구 체크 추천에 나오게 하려면 ‘해당하는 요구’를 지정한다. 파일 내용을 읽어 조건·기관·요구를 자동 추측하지 않는다. 파일만 저장하고 요구를 선택하지 않은 서비스도 검색/목록에서 사용할 수 있다.
6. 공개자료를 편집하려면 해당 사업의 ‘공문·양식 업로드’로 개인 복사본을 만들거나, 기존 ‘가져오기·백업’의 선택 병합을 이용한다. 공개 원본과 타인 자료는 바뀌지 않는다.
7. 본인 요구 항목은 ‘요구 항목’에서 추가·수정한다. 저장된 분류와 ID는 유지하며 체크 화면에서는 공통 분야 메뉴에 통합한다. 분류가 불명확한 개인 항목은 기관 연결 메뉴에 표시한다.
8. ‘가져오기·백업’에서 주기적으로 개인 목록을 백업한다. JSON에는 양식 파일 본문이 아닌 Drive 파일 ID가 들어 있다. 다른 계정으로 JSON만 옮긴다고 원래 계정의 파일 접근권한까지 이전되지는 않는다.

개인 목록·양식은 동일 Google 계정으로 다른 기기에서 다시 연결해 사용할 수 있다. 기능 켜기/끄기는 **현재 브라우저의 Google 계정별 설정**이며 기기 간 동기화되지 않는다. 기능 숨기기는 데이터를 지우지 않는다. 자세한 내용은 [FEATURES.md](FEATURES.md)를 참고한다.

## 확인 필요 사업에 서류 등록

- ‘담당기관 확인 필요’에서 사업의 ‘공문·양식 업로드’를 누른다. 상세 화면에도 업로드/관리 버튼이 있다.
- 본인 Drive를 연결한 상태에서 개인정보 없는 공문·빈 신청양식을 선택한다. 기존과 동일하게 파일당 최대 20MiB까지 업로드한다. HWP·PDF 등 일반 파일을 첨부할 수 있다.
- 업로드 성공 후 ‘저장’을 눌러야 개인 목록에 연결되고 확인 대기가 해제된다. 상태는 **개인 자료 등록 완료 (공식 검증 아님)**으로 표시한다.
- 링크만 넣거나 텍스트 확인 기록만 작성한 경우에는 대기를 해제하지 않는다. 업로드/목록 저장이 실패하거나 편집을 취소하면 완료 처리하지 않는다.
- 마지막 파일 연결을 제거하고 저장하면 개인 확인 대기로 돌아간다. 연결 제거·서비스 삭제는 파일 자체를 자동 영구 삭제하지 않는다. 파일 정리는 본인 Drive에서 한다.
- 업로드 뒤 저장을 취소하거나 충돌이 생기면 연결되지 않은 파일이 Drive에 남을 수 있다. 기존 자료 보호를 위해 자동 삭제하지 않으며, 필요하면 본인이 정리한다.
- 연계 양식은 ‘보관함’의 7일 자동삭제 자료가 아니다. 연계자료 폴더에 계속 보관된다.

**개인 자료 등록 완료는 서류가 연결됐다는 뜻이다.** 파일 내용을 분석해 공문 진위·현재 사업 운영·강서구 대상 여부·접수 가능·지원 자격을 검증하지 않는다. 기존 ‘미확인’ 접수 상태와 의뢰 방식·자격조건은 그대로 남는다. 공개 카탈로그의 확인 필요 21건은 원본 기준이며, 본인 업로드 후의 내 확인 대기 건수는 별도로 계산된다. 다른 이용자에게는 그 사람의 등록 자료에 따라 표시된다.

## 웹사이트 자체를 별도로 바꾸려는 경우

개인 목록 편집과 달리 디자인·공개 기본자료·코드를 바꾸거나 별도 주소로 운영하려면 소스 개발이 필요하다.

- GitHub 계정으로 저장소를 fork하거나 본인 저장소에 복제할 수 있다. 공개 저장소의 GitHub Pages는 무료 계정으로 운영할 수 있으며 유료 GitHub 구독이 기본 조건은 아니다. 비공개 운영과 조직 정책은 별도 확인한다.
- Python·Node.js·Chromium 등의 개발 도구로 빌드·테스트한다. AI의 도움은 선택 사항이다. ChatGPT 유료 구독이 사이트 운영 조건은 아니며, Codex 등 원하는 개발 도구의 이용 가능 범위는 해당 계정/요금제에서 별도로 확인한다.
- `ui-source/`, `src/`, `data/`를 수정하고 `python3 build_site.py`, 루트 HTML 동기화, 테스트를 거쳐 소스·빌드 결과를 함께 관리한다. 생성된 `index.html`만 직접 수정하지 않는다.
- 새 배포 주소를 쓰면 본인 Google OAuth 프로젝트/클라이언트와 Calendar·Drive API, 승인된 원본/리디렉션 주소, 동의 화면을 새 운영에 맞게 설정해야 한다. 원본 사이트의 클라이언트 ID를 복사했다고 새 주소에서 로그인되는 것은 아니다.
- 피드백을 별도 운영하려면 Firebase 설정·보안 규칙·관리자 계정도 본인 운영으로 분리한다. 원본 운영자의 피드백 프로젝트를 그대로 공유 운영하는 것으로 가정하지 않는다. [FEEDBACK.md](FEEDBACK.md)를 참고한다.
- 실제 사용자 Drive 자료·작성된 대상자 서류·개인정보를 GitHub 저장소에 올리지 않는다. 일반 이용자에게 원본 저장소의 수정 권한을 줄 필요는 없다.
